Section 1

The operating system

What an operating system is for

Your program wants to read a file. It does not know what a disk is, and it must not read anyone else's files. The OS sits in between.

  • Abstraction – one open() call for an SSD, a network share or a USB stick.
  • Isolation – your crash does not take down the machine.
  • Scheduling – 400 processes, 8 cores, everyone takes a turn.
┌────────────────────────────────────┐
│  your Python script                │
├────────────────────────────────────┤
│  shell and libraries (bash, libc)  │
├────────────────────────────────────┤
│  system calls: open read write     │
├────────────────────────────────────┤
│  kernel: processes, memory, files  │
├────────────────────────────────────┤
│  hardware                          │

Fifty-five years in nine lines

1969Ken Thompson and Dennis Ritchie build Unix at Bell Labs. Small tools, plain text, one filesystem tree.
1973Unix is rewritten in C – so it can be moved to other machines. This is why it survived.
1983Richard Stallman starts GNU: a free Unix. The tools get written, the kernel does not.
1991Linus Torvalds, a student in Helsinki, posts a hobby kernel. "Just a hobby, won't be big."
1992GNU tools + Linux kernel = a complete free operating system. Licensed GPL, so improvements come back.
1990sDistributions appear – Debian, Red Hat, Slackware. A kernel, the tools, a package manager, defaults.
2003Linux takes over the server room. Cheaper than Unix, better than the alternatives.
2008Android ships on a Linux kernel. It becomes the most-used OS on earth.
2013Docker makes Linux the unit of deployment. Every container image is a Linux filesystem.

POSIX is the standard that keeps them compatible. macOS is certified Unix, so nearly everything today works identically on your Mac and on a cloud server. On Windows, use WSL2 – a real Linux kernel.

Why this is not history homework

  • Every cloud VM, container and CI runner you touch is Linux.
  • Your notebook runs on someone's Linux box. When it fails at 2am, the only interface is a shell.
  • A Dockerfile is a list of shell commands. So is most of a CI pipeline.
  • Debugging a deployment means reading logs, checking permissions and following processes – all of it in the terminal.
an ordinary Tuesday 
$ ssh data@prod-etl-01
$ cd /var/log/etl
$ tail -f pipeline.log
$ grep -c ERROR pipeline.log

No IDE, no mouse, 400ms of latency. This is a normal amount of terminal for a data engineer.

Section 2

Terminal 101

Terminal, shell, prompt – three different things

  • Terminal – the window. Terminal.app, iTerm, Windows Terminal, the VS Code panel.
  • Shell – the program inside it that reads your commands. bash, zsh, fish. macOS defaults to zsh; servers almost always give you bash.
  • Prompt – the text the shell prints when it is ready for you.

echo $SHELL tells you which shell you are in. Everything today works in both bash and zsh.

charlotte@laptop:~/projects/etl$
└───┬───┘ └──┬──┘ └─────┬─────┘└┬┘
    user   machine    where     you are
                       you are  not root
                       ($ vs #)

In these slides the prompt is shown as a bare $. Do not type it – it is the shell's, not yours.

Every command has the same shape

$ ls  -l  -a  --human-readable  /var/log
  │   └────────┬─────────────┘  └───┬──┘
  │        options/flags        arguments
  └── the program

$ ls -lah /var/log            short flags combine
  • Single dash, single letter: -l. Double dash, whole word: --all.
  • Case matters. -r and -R are usually different things.
  • Spaces separate arguments – which is why My File.txt needs quotes.
when you do not know a flag 
$ ls --help
$ man ls           # q to quit, / to search
$ type ls

One tree, from /

/               the root of everything
├── bin/        essential programs: ls, cp, bash
├── etc/        system configuration, all text
├── home/       one directory per user
│   └── charlotte/     = ~
├── var/        things that change
│   └── log/           logs live here
├── tmp/        wiped on reboot, anyone can write
├── usr/        installed software
│   ├── bin/           most of your programs
│   └── local/         things you installed
├── opt/        third-party bundles
├── dev/        devices as files (/dev/null)
└── proc/       the kernel, as files

No drive letters. A USB stick, a network share and a second disk all appear as directories somewhere in this one tree.

  • /etc is where you go when something is configured wrong.
  • /var/log is where you go when something is broken.
  • /dev/null discards anything written to it. You will use it to silence output.

Press Tab. Always. It completes paths and commands, and it will not complete something that does not exist – so it is also a spell checker. Twice shows you the options.

Reading files without opening an editor

$ cat notes.txt          # whole file, at once
$ less pipeline.log      # scroll; q quits
$ head -20 data.csv      # first 20 lines
$ tail -20 data.csv      # last 20
$ tail -f pipeline.log   # follow as it grows
$ wc -l data.csv         # count lines
$ file mystery.bin       # what is this?
$ stat data.csv          # size, dates, perms
  • head on an unfamiliar file, every time. cat on a 2 GB CSV locks up your terminal.
  • tail -f is how you watch a job run. Ctrl+C to stop watching.
  • In less: / searches, n next match, G jumps to the end, q quits.

cat file | grep x works, but grep x file is what you meant.

Creating, copying, moving, deleting

$ mkdir reports
$ mkdir -p data/raw/2026     # whole path
$ touch report.md            # empty file

$ cp report.md backup.md
$ cp -r data/ data-backup/   # directories
$ mv report.md docs/         # move
$ mv report.md notes.md      # rename

$ rm backup.md
$ rm -r data-backup/         # directory
$ rmdir empty-dir/           # only if empty

There is no recycle bin. rm is immediate and permanent. No confirmation, no undo, no reflog.

rm -rf / # the meme
rm -rf $DIR/* # the real
  # danger: if
  # DIR is unset
  # this is rm -rf /*

Habits: ls the pattern before you rm it. Quote your variables. Never rm -rf a path you built by string concatenation without checking it first.

Finding things: find and grep

find – by name, size, age 
$ find . -name "*.csv"
$ find . -iname "*README*"      # any case
$ find . -type d -name "test*"  # dirs only
$ find . -size +100M            # big files
$ find . -mtime -1              # last 24h
$ find . -name "*.pyc" -delete
grep – by content 
$ grep ERROR pipeline.log
$ grep -i error pipeline.log    # any case
$ grep -n ERROR pipeline.log    # line numbers
$ grep -c ERROR pipeline.log    # just a count
$ grep -v DEBUG pipeline.log    # invert
$ grep -r "VAT_RATE" src/       # recursive
$ grep -A2 -B2 ERROR log        # context

find looks at names, grep looks inside files. Quote your patterns – *.csv unquoted gets expanded by the shell before find ever sees it.

Pipes: the idea the whole system is built on

Every program reads a stream of text and writes a stream of text. So any program's output can be any other program's input.

$ grep ERROR pipeline.log | cut -d' ' -f4 | sort | uniq -c | sort -rn | head -5

  only errors  →  the module  →  group  →  count  →  biggest  →  top 5
output 147 invoice.py 31 loader.py 9 vat.py

Redirection: sending streams somewhere else

$ echo "hi" > out.txt       # write (replaces!)
$ echo "again" >> out.txt     # append
$ sort < names.txt            # read from file

$ python3 job.py > out.log 2> err.log
$ python3 job.py > all.log 2>&1
$ python3 job.py 2> /dev/null  # hide errors
$ python3 job.py | tee run.log  # screen + file
StreamNumberIs
stdin0what comes in
stdout1the results
stderr2the complaints

They are separate on purpose: | grep filters the results without swallowing the error messages.

> truncates the file before the command runs. sort file.txt > file.txt gives you an empty file.

The text tools worth memorising

$ wc -l data.csv           # count lines
$ sort names.txt
$ sort -rn sizes.txt       # reverse numeric
$ uniq -c                  # count runs
$ cut -d, -f2,5 data.csv   # pick columns
$ tr 'a-z' 'A-Z'           # translate chars
$ sed 's/old/new/g' f.txt  # substitute
$ head -1 data.csv         # the header
$ awk -F, '{print $2}' f   # field 2
$ xargs rm                 # args from stdin
worked example 
# most common values in column 3
$ tail -n +2 sales.csv \
  | cut -d, -f3 \
  | sort | uniq -c | sort -rn \
  | head -3
  • uniq only removes adjacent duplicates. It is nearly always sort | uniq.
  • A backslash at the end of a line continues the command. Use it on long pipelines.

chmod, and the number everyone remembers

$ chmod +x deploy.sh        # make runnable
$ chmod u+w,go-w notes.md   # symbolic
$ chmod 755 deploy.sh       # numeric
$ chmod 600 ~/.ssh/id_ed25519
$ chmod -R 755 public/      # recursive

$ chown charlotte:staff file   # needs sudo
755rwxr-xr-xprogram, or a directory
644rw-r--r--an ordinary file
600rw-------a secret. SSH keys
777rwxrwxrwxnever the right answer

Add the digits: read 4 + write 2 + execute 1. Three digits, for user, group and other.

chmod 777 is how "Permission denied" becomes "security incident". It is the shell equivalent of except: pass – the error goes away and the problem remains.

Work out which permission is missing instead.

sudo runs one command as root. Read the command twice before you press enter.

Processes: what is running, and stopping it

$ ps aux | grep python
$ top          # live; q quits
$ htop         # nicer, if installed

$ python3 long_job.py &      # background
[1] 48213
$ jobs
$ fg %1                      # bring it back
$ kill 48213                 # ask it to stop
$ kill -9 48213              # make it stop
$ pkill -f long_job.py       # by name

$ nohup python3 job.py &     # survives logout

Every running program is a process with a PID and a parent. kill sends it a signal; the default asks politely and lets it clean up.

Environment variables and PATH

$ echo $HOME
/home/charlotte
$ echo $PATH

$ export API_TOKEN="abc123"
$ python3 -c \
  "import os; print(os.environ['API_TOKEN'])"

PATH is a list of directories, checked left to right, to find the program you typed. which tells you which one won – that is how you know your virtual environment is active.

export lasts for this shell session only. To make it permanent, add the line to ~/.zshrc (macOS) or ~/.bashrc (Linux), then source it.

Never put a secret in .bashrc or in your shell history. Use a .env file that is in .gitignore, or your platform's secret store.

Section 3

Bash scripting 101

A script is the commands you typed

setup.sh 
#!/usr/bin/env bash
# Set up a fresh project directory.
set -euo pipefail

mkdir -p src tests data
python3 -m venv .venv
echo ".venv/" > .gitignore
git init

$ chmod +x setup.sh
$ ./setup.sh
  • The shebang on line 1 says which interpreter to use. env bash finds it wherever it lives.
  • chmod +x once, then ./setup.sh. The ./ is required: this directory is not on your PATH.
  • Comments start with #. Line 1 only looks like one.

Variables, and the quoting rule

name="Charlotte"          # no spaces around =
greeting="Hello, $name"
today=$(date +%F)         # command output
count=$((2 + 3))          # arithmetic

echo "$greeting, $today"

readonly MAX_RETRIES=3

Always quote your variables.

file="My Report.csv"

rm $file
# deletes "My" and "Report.csv"

rm "$file"
# deletes the file you meant

"double quotes" expand variables. 'single quotes' do not. Unquoted splits on spaces and expands *.

The single most common bug in shell scripts, by a wide margin.

Arguments and exit codes

backup.sh 
#!/usr/bin/env bash
set -euo pipefail

if [[ $# -lt 1 ]]; then
    echo "usage: $0 <directory>" >&2
    exit 1
fi

src="$1"
target="${2:-/tmp/backup}"

tar -czf "$target/$(date +%F).tgz" "$src"
echo "Backed up $src to $target"
$0the script's own name
$1, $2first, second argument
$#how many arguments
"$@"all of them, safely quoted
$?exit code of the last command
${2:-x}$2, or x if unset

0 means success, anything else is a failure. That is backwards from Python's truthiness and it catches everyone once.

Errors go to stderr (>&2) and failures exit 1, so the caller – a pipeline, a cron job, CI – can tell.

Conditionals

if [[ -f "$file" ]]; then
    echo "file exists"
elif [[ -d "$file" ]]; then
    echo "it is a directory"
else
    echo "nothing there"
fi

if [[ "$env" == "prod" ]]; then ... fi
if [[ $count -gt 10 ]]; then ... fi
if grep -q ERROR log; then ... fi

command -v jq >/dev/null || {
    echo "jq is required" >&2; exit 1
}
-f / -d / -eis a file / directory / exists
-z / -nstring is empty / not empty
== / !=string comparison
-eq -ne -gt -ltnumber comparison

Use [[ ]], not [ ]. It handles empty variables and spaces without surprises.

An if can test any command directly – it is checking the exit code, not a boolean.

Loops, functions and case

for file in data/*.csv; do
    echo "Processing $file"
    python3 load.py "$file"
done

for i in {1..5}; do echo "$i"; done

while read -r line; do
    echo "> $line"
done < names.txt

until curl -sf "$url"; do sleep 2; done

log() {
    echo "[$(date +%T)] $*" >&2
}

log "starting"

case "${1:-}" in
    start)  log "starting" ;;
    stop)   log "stopping" ;;
    *)      echo "usage: $0 start|stop" >&2
            exit 1 ;;
esac

for f in data/*.csv loops over filenames safely, spaces included. Never loop over $(ls).

The three lines at the top of every script

set -euo pipefail
-estop at the first failing command
-ua typo in a variable name is an error, not an empty string
-o pipefaila pipeline fails if any stage fails, not just the last
without it 
#!/usr/bin/env bash
cd "$BUILD_DIR"     # typo: unset
rm -rf *            # in your home dir
with it 
$ ./build.sh
./build.sh: line 3: BUILD_DIR: unbound variable
$ echo $?
1

Bash's defaults are from 1989 and assume you are typing interactively. In a script they will hurt you. This line is not optional.

When to stop writing bash

Bash is right for

  • Gluing commands together in order.
  • Moving files, setting up directories, running other programs.
  • Anything under about 50 lines.
  • Something that must run on any machine with no dependencies.

Switch to Python when

  • You need arithmetic, dates or floating point.
  • You are parsing JSON, CSV or XML.
  • You want data structures, functions with return values, or tests.
  • You have written a second nested if inside a loop.
  • You cannot tell what your own script does.

Run shellcheck on every script you keep. It finds the unquoted variables and the wrong test operators before they find you: brew install shellcheck.

Take home

Bash scripting

  1. greet.sh NAME – greets by name, or prints a usage line and exits 1 if no name is given.
  2. count.sh DIR – how many files, directories and lines of Python it contains.
  3. backup.sh SRC [DEST] – makes a dated .tgz of SRC, defaulting DEST to /tmp/backups. Refuse if SRC does not exist.
  4. newproject.sh NAME – creates src/, tests/, a .gitignore, a virtual environment, a README and an initial commit.
  5. Bonus. logstats.sh LOGFILE – top 5 errors with counts, and the busiest hour. Pipes only.

Section 4

SSH

A shell on someone else's machine

SSH gives you an encrypted terminal session on a remote host. Same commands, same shell, different computer.

You authenticate with a key pair, not a password:

  • The private key stays on your laptop. It never moves, ever.
  • The public key is copied to the server. It is safe to share.
  • The server sends a challenge only the private key can answer.
$ ssh charlotte@prod-etl-01
charlotte@prod-etl-01:~$ hostname
prod-etl-01
charlotte@prod-etl-01:~$ exit
$

$ ssh -p 2222 charlotte@host      # other port
$ ssh charlotte@host "df -h"      # one command

Nothing is transmitted that would let an eavesdropper log in as you – which is why passwords are switched off on any serious server.

Making and installing a key

$ ssh-keygen -t ed25519 -C "charlotte@laptop"
Enter passphrase: ********

$ ls -l ~/.ssh
-rw-------  id_ed25519        ← private. 600
-rw-r--r--  id_ed25519.pub    ← public

$ ssh-copy-id charlotte@host
$ ssh charlotte@host           # no password

$ ssh-add ~/.ssh/id_ed25519   # cache the pass
  • Use ed25519. Short, fast, modern.
  • Set a passphrase. It is what stops a stolen laptop becoming a stolen server. ssh-add means you type it once per session.
  • On the server, public keys live in ~/.ssh/authorized_keys – one per line.

Permissions are enforced. SSH refuses a private key others can read: chmod 600 the key, 700 the directory.

Stop typing the long version: ~/.ssh/config

~/.ssh/config 
Host etl
    HostName prod-etl-01.example.com
    User charlotte
    Port 2222
    IdentityFile ~/.ssh/id_ed25519

Host github.com
    User git
    IdentityFile ~/.ssh/id_ed25519

$ ssh etl
moving files 
$ scp report.csv etl:/data/incoming/
$ scp etl:/var/log/etl.log ./

$ rsync -avz --progress data/ etl:/data/
  • scp for one file. rsync for a directory – it only sends what changed and can resume.
  • A trailing slash on the rsync source means "the contents of", not "the directory". This matters.

Where this connects back to Git

$ ssh-keygen -t ed25519 -C "charlotte@laptop"
$ cat ~/.ssh/id_ed25519.pub
ssh-ed25519 AAAAC3Nza... charlotte@laptop

# paste that into
# GitHub → Settings → SSH and GPG keys

$ ssh -T git@github.com
Hi charlotte! You've successfully
authenticated.

$ git clone git@github.com:roots/academy.git

This is why git clone git@github.com:… works without a password.

  • The git@ address is SSH. The https:// address needs a token instead.
  • One key per machine, not per repository.
  • Lost the laptop? Delete that public key in GitHub settings and the access is gone.

ssh -T git@github.com is the fastest way to check whether your key is set up. Do it now.

Recap

The whole day, in one page

Git

  • Commits are snapshots; branches are pointers.
  • status and diff before every commit.
  • Branch, push, pull request, review, merge.
  • Conflicts are questions, not damage.
  • If it was committed, the reflog can find it.

Python

  • Four containers, chosen on purpose.
  • Functions take arguments and return values.
  • Mutable defaults and shared references bite.
  • Raise early, catch specifically.
  • One virtual environment per project.

Linux

  • One tree from /, text streams between programs.
  • Pipes and redirection compose small tools.
  • rm has no undo. 777 is never the fix.
  • set -euo pipefail on every script.
  • Private key stays home; public key travels.

Three cheat sheets are in cheatsheets/. Print them. The exercises stay in the repository – push your solutions to your personal branch and open a pull request.

The habit that matters more than any of it

When something breaks, read the error message. All of it. Out loud if necessary.

  • Python tells you the file, the line and the type of problem. Start at the bottom.
  • Git tells you what it refused to do and usually suggests the command that fixes it.
  • The shell tells you which file it could not find or write.
  • Change one thing at a time, then look again.
  • Say what you expected and what happened. That sentence solves half of them by itself.
  • Then ask a colleague. Fifteen minutes stuck is learning; ninety is waste.

Nobody remembers the flags. Everybody knows how to find them.
